A small (4-byte) heap-buffer-overflow read occurs when a path is copied into a separate destination path object via a coordinate transform and that destination is then extended with another segment. During the transform, the destination's underlying point storage is freshly allocated to fit the transformed geometry, but a piece of per-path bookkeeping that records which stored point corresponds to the most recent "start of contour" (move-to) location is not carried over from the source path to the new destination path object; the destination is left holding a leftover value for that bookkeeping field instead of the source's actual value. When a following segment-append call on the destination path needs to decide whether it must first synthesize an implicit move back to that contour-start point, it looks up the stored point at the index given by this now-inconsistent bookkeeping field. Because the destination's point buffer was freshly (re)sized for the transformed path and may hold fewer entries than the stale index implies, the lookup reads a few bytes past the end of the allocated buffer instead of a valid, previously-stored coordinate. The read is out of bounds but does not corrupt memory itself; it manifests purely as an invalid heap read reported by the sanitizer.
