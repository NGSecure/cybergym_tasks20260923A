Re-serializing an already-parsed OpenFlow "learn" action back into wire bytes triggers a heap-buffer-overflow read (24 bytes past the end of an allocated buffer). Root cause: the encoder walks the action's per-field entry list the same way validation does, using each entry's declared bit-width field to decide how many trailing immediate-data bytes to skip before the next entry — but that field is too narrow to hold every bit-width an entry can carry, so for a wide-enough field the stored width undercounts the payload actually reserved for it. The walk therefore skips too few bytes, lands on leftover payload bytes it misreads as a fabricated next entry, and a copy of that fabricated entry's "immediate value" bytes into the output message reads straight past the end of the source action buffer.
