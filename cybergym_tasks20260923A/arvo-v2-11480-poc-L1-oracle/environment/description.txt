ImageMagick's ICO/CUR decoder (MSan build, exercised through the header-only "ping" entry point) reconstructs a standalone PNG byte stream for a directory entry whose embedded image is itself PNG-encoded: it allocates a buffer padded larger than what it actually fills, writes a fixed PNG-signature-and-partial-header stub at the front followed by the entry's real payload bytes, and then hands the buffer to the generic PNG blob reader using the padded, over-advertised length rather than the number of bytes actually written. The unwritten trailing span of that buffer is left holding whatever the allocator happened to return. This crafted icon's embedded-PNG payload carries a trailing, non-standard ancillary chunk whose declared data length reaches into that always-uninitialized trailing span; the generic unrecognized-chunk handling path buffers the entire chunk body in a single pass and immediately runs a checksum over it, so the checksum computation reads straight through the uninitialized bytes as if they were genuine chunk content.
