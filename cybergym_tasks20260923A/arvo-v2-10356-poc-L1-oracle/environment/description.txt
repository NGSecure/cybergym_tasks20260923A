HarfBuzz (ASan build): parsing a crafted legacy Mac "dfont" (resource-fork-wrapped) font with hb_face_create() and then looking up a table by tag inside its embedded sfnt directory causes a 1-byte heap-buffer-overflow read. Root cause: several offset fields inside the resource-fork container (from the fork header to its data block and resource map, and from the map to its type list and resource list) are declared as nullable, so a zero offset is treated as "absent" and the validator skips bounds-checking whatever it would point to; a crafted file that sets one of these offsets to zero thereby lets an entire unvalidated sub-structure -- down to the embedded sfnt's own table directory -- be dereferenced as if it were valid, so the later table-lookup reads a length field that lies just outside the allocated blob.
