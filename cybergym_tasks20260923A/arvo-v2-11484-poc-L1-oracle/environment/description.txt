A crafted OPC UA binary message that decodes into a complex value holding a heap-allocated array of sub-elements (e.g. an array-valued variant) triggers a heap-use-after-free in open62541's core type-teardown code when that array payload gets torn down twice along the library's copy-failure cleanup path. Root cause: the routine that releases a variant's array data frees it via the generic array-teardown helper but never resets the now-dangling pointer afterward, so when the same value is torn down a second time — which happens when an outer copy operation rolls back a partially-completed nested/deep copy — the stale pointer is walked again and the recursive teardown dereferences already-freed array elements.
