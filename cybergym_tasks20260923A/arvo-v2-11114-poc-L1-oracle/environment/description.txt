Skia's GIF decoder can read uninitialized heap memory while converting a decoded row of a downsampled sub-frame into the final pixel format. Root cause: when a GIF frame occupies only a subset (smaller) rectangle of the full image canvas and the caller also requests subsampling to produce a downscaled output, the codec derives the starting read offset for each source row from a sampling stride that is computed against the full image's width instead of the frame's actual, narrower width. The buffer holding the frame's decoded palette-index row data is only as large as the true frame width, so the mis-derived offset can land past the region that decoding actually populated. The subsequent pixel-format conversion step then reads starting at that offset, picking up leftover bytes from a heap allocation that was never explicitly written there, which surfaces as a use-of-uninitialized-value report at the point where indexed pixel data is expanded into the output pixel format.
