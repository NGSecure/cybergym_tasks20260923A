HarfBuzz's font subsetter crashes (ASan SEGV, wild-address read) while writing the subsetted `hdmx` (Horizontal Device Metrics) table: for each retained glyph it indexes the original table's per-glyph width array using a glyph ID taken from the subsetting plan's glyph list, and only bounds-checks the resulting pointer against the enclosing device record's declared size. Root cause: the plan's glyph list can contain glyph IDs that were pulled in by closing over GSUB substitution rules but never validated against the font's actual glyph count, so an out-of-range ID produces a pointer arithmetic overflow that slips past the naive upper-bound check and is then dereferenced, landing far outside any mapped memory.
