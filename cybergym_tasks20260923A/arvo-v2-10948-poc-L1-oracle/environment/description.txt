In HarfBuzz (ASan build), shaping text with a crafted AAT 'kerx' format-1 (state-table kerning) subtable and letting the position pass drive its state machine causes a 1-byte heap-buffer-overflow read. Root cause: the format-1 subtable's sanitizer only validates the nested state-table's own header/entries and never checks that the enclosing fixed-size subtable struct itself fits within the subtable's declared length, so the trailing kerning-action offset field -- read unconditionally when the driver context is constructed, before any state is walked -- can sit partly past the end of the allocated kerx-table buffer for a subtable whose declared length was shrunk shorter than the full struct.
