harfbuzz (ASan build, hb-shape-fuzzer target): checking whether a crafted font's legacy "kern" table carries any kerning data triggers a heap-buffer-overflow read during shaping. Root cause: the table's sanitizer validates only the first 2 bytes of a union that overlays the table's leading field -- enough to cover a 16-bit "major version" reading of it -- before declaring the table safe, but the has-data check invoked right after (via the kerning-support probe during shape planning) instead reads the union as a full 4-byte big-endian version value; for a table whose subtable data ends immediately after those 2 sanitized bytes, the extra bytes pulled in by the wider read run past the allocated buffer.
