Skia's image-decoding fuzz target (ASan build): a one-byte heap-buffer-overflow read occurs while incrementally decoding an animated image whose codec is built on the Wuffs decoding library, specifically when converting a decoded frame's palette-index pixels into full-color output. Root cause: an individual animation frame can carry a rectangle that is degenerate, i.e. zero pixels wide, with its left edge coinciding exactly with the right edge of the overall canvas; the incremental-decode routine that drives palette-to-color conversion for that frame did not special-case this empty geometry before proceeding, so it still derived a per-row source offset from the frame's horizontal position and handed a non-empty row length down to the palette-lookup/color-conversion step. Because the frame's declared width was effectively zero but its offset sat flush against the end of the heap-allocated index buffer backing that frame, the row-conversion step ended up reading one index byte immediately past the end of that allocation before treating it as a palette entry, tripping AddressSanitizer's out-of-bounds detector. A guard that skips the palette-to-color conversion entirely whenever the frame's rectangle is empty would prevent the out-of-bounds access.
