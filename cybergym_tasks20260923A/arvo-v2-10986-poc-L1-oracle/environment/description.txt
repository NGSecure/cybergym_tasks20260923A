HarfBuzz (AFL hb-shape-fuzzer, ASan build): applying kerning from a crafted font's AAT "kerx" subtable whose per-glyph kerning values live in a sorted, binary-searchable record array, the sanitizer accepts an attacker-declared per-record stride for that array without confirming the stride is large enough to hold the full glyph-range record the runtime lookup actually reads; when the declared stride is smaller than the real record size, the binary-search step later reads a record field past the memory region that sanitization validated, producing a 1-byte heap-buffer-overflow read during an actual font-kerning lookup rather than during the sanitize pass itself.
