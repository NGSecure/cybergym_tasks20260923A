Open vSwitch's datapath action string parser (ASan build) hits a heap-buffer-overflow read while decoding a nested set(tunnel(...)) action whose VXLAN-GBP metadata sub-block is truncated: the internal helper for that sub-block, on failing to find the expected tunnel-ID field, returns a negative errno value instead of the shared scanner convention's zero-means-no-match sentinel, so the enclosing key parser misreads it as a valid consumed-length and moves the cursor backward out of the allocated input buffer before the next byte is dereferenced.
