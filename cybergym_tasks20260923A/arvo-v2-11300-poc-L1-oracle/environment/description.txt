yara's .NET PE metadata analysis module (MSan build) suffers an out-of-bounds read while walking the assembly-reference table of a crafted .NET binary. Inside the per-row loop that decodes each AssemblyRef entry, the row pointer used to dereference table fields is advanced on every iteration, but the bounds check guarding each iteration keeps re-validating the position where the table started rather than the pointer's current, already-advanced location; once a crafted row count (or an undersized backing table) pushes an iteration past the first row, the stale check still reports the access as in-bounds, so the code dereferences a row pointer that now sits outside the mapped PE image and reads unmapped/uninitialized memory.
