A use-of-uninitialized-value warning fires while a path's contour data - its draw verbs together with the associated points and curve weights - is walked back-to-front and copied into a fresh path object as part of building a reversed, appended version of that path's geometry. Just before the walk begins, the destination's storage for points and for verbs is allocated using the source's verb count and point count swapped with each other, rather than each buffer being sized by its own matching quantity. Because points and verbs generally differ in number, one of the two freshly allocated buffers ends up under-covered relative to what the copy loop actually writes into it afterward, so a trailing portion of that buffer is left holding whatever bytes the allocator happened to return rather than real per-point coordinate data. Sometime later, an unrelated routine that recomputes the path's overall bounding box performs a batched, vectorized check across a block of the path's stored points; it reads that never-written tail region as if it held valid coordinates, and the sanitizer flags the read as consuming uninitialized memory rather than as any observable corruption.
