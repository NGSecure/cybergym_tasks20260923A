ImageMagick's ICO/CUR decoder (MSan build, exercised through the header-only "ping" entry point), when a directory entry's embedded image is itself PNG-encoded rather than a raw bitmap, reconstructs a standalone PNG byte stream in a freshly allocated buffer: it writes a fixed PNG-signature-and-partial-header stub at the front, copies the entry's real payload bytes right after that stub, and then hands the whole buffer to the generic PNG blob reader with a declared length equal to stub-plus-payload plus a fixed pad. Only the stub and the real payload are ever written into the buffer, which is short of what was allocated and advertised by that same fixed pad, so a trailing span of the reconstructed stream is uninitialized heap memory that the decoder is nonetheless told it may consume. This crafted icon's embedded-PNG payload is shaped so that the declared-length field of the very next chunk header, immediately following the copied payload, falls inside that always-uninitialized trailing span rather than inside real payload bytes, so the decoder reads an uninitialized value the moment it tries to determine how long the following chunk is.
