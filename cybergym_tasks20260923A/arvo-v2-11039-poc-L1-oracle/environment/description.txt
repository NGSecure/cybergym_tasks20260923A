A fuzz target decodes an image file into a bitmap using one of Skia's image codecs and then draws the resulting bitmap onto a canvas, which triggers a MemorySanitizer use-of-uninitialized-value warning. The bitmap's pixel buffer is allocated with a plain, non-zero-initializing heap allocation, so any byte the codec never explicitly writes stays uninitialized; to guarantee every pixel is defined, the codec is supposed to run a fallback pass that backfills whatever rows or columns an incomplete or interrupted decode (for example a sampled or scanline-based decode that has to stop partway through the image) never got around to writing. For at least one such incomplete-decode scenario, that backfill pass does not cover the full portion of the buffer that still needs it, so part of the allocated pixel memory is left uninitialized even though the decode is treated as finished. Because the rest of the pipeline assumes a fully-initialized buffer, the bitmap is later drawn by compositing every pixel unconditionally through an optimized blitting routine, and it is that unconditional read of the still-uninitialized bytes that MemorySanitizer flags, so the actual defect lives in the codec's incomplete-decode fill and initialization logic rather than in the drawing code where the crash is observed.
