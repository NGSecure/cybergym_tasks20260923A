ImageMagick (MSan build): decoding a LABEL image whose embedded `%[...]` property-format text contains a brace-style alternation pattern (e.g. `{foo,bar}`) triggers a use-of-uninitialized-value read while ImageMagick's wildcard/glob matcher checks that pattern against the name of an already-registered image property during percent-escape expansion. Root cause: once one comma-separated alternative inside the braces is found to match, the matcher advances its cursor into the property-name string it just matched against by the raw byte length of that attacker-controlled alternative text, instead of clamping the advance to however many bytes actually remain in the property name being scanned. Because the fuzzer-supplied alternative can be longer than the (often short, internally generated) property name it matched, the cursor is pushed past that name's terminating NUL byte into the unwritten padding bytes of the same heap allocation. The matcher then hands one of those never-written padding bytes to its multi-byte character decoding step as if it were the next character to read, which is what MemorySanitizer flags.
