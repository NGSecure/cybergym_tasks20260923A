HarfBuzz's CFF (Compact Font Format) table accelerator, exercised through the subset-fuzzer's font-subsetting path (ASan build): parsing a CID-keyed CFF font whose per-subfont ("Font DICT") dictionary is malformed triggers a heap double-free while the accelerator is being torn down. Root cause: each subfont's dictionary parser accumulates its parsed operand entries into its own small growable buffer, and that per-subfont record is itself one element of an outer growable collection holding all of the font's subfont dictionaries. When parsing of one subfont's dictionary fails partway through, the accelerator's setup routine reacts by running a "deep" cleanup pass over that outer collection, freeing every subfont record's operand buffer allocated so far. The accelerator's own teardown routine, however, unconditionally repeats that same deep-cleanup pass whenever the accelerator object is destroyed or explicitly finalized, without first checking whether the earlier, error-triggered cleanup pass already ran and already released those buffers. On this crafted input, both cleanup passes end up operating on the same live collection state, so one subfont's already-freed operand buffer gets handed to free() a second time, aborting the process under AddressSanitizer.
