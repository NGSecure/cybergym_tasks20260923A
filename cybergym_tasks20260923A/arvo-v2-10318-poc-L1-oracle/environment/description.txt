Skia's path-manipulation fuzz target (ASan build): a heap-use-after-free read occurs when a path object's reversed copy is appended back into that very same path object. Root cause: the reversal routine takes raw pointers into the source path's shared backing storage (its point array, verb array, and conic-weight array) before it starts emitting the reversed segments into the destination, but when the source and destination happen to be the same underlying path, each emitted segment is written through the ordinary append path, which can grow and reallocate that same shared backing storage; the routine never detects this self-append aliasing case, so once growth triggers a reallocation partway through, the pointers it captured at the start now point into memory that has already been freed, and a subsequent read through one of them touches freed heap memory instead of the still-live reallocated buffer.
