An 8-byte heap-buffer-overflow read occurs while one path's stored contour data (its sequence of draw verbs together with the associated points and curve weights) is walked in order to copy each segment into another path, a step used when appending one path's geometry onto another. The walking code assumes a path invariant: every segment other than an explicit "move to the start of a new contour" has a point immediately preceding it in the point buffer, representing where the previous segment left off, and it reads that preceding slot directly by indexing one element behind its current cursor rather than tracking the value separately. For a path built and modified through certain sequences of contour/segment operations, that invariant can end up violated: the walk can reach a non-move segment as effectively the first thing it processes for that contour, with no valid preceding point actually present in the buffer at that position. Indexing "one point before the cursor" in that situation lands one point's width (8 bytes) before the start of the allocated point storage, producing an out-of-bounds heap read rather than a legitimate previously-stored coordinate.
