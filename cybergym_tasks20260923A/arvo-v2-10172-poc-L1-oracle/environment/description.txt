Wireshark's ASan build hits a 1-byte heap-buffer-overflow read while dissecting a crafted SLPv1 (Service Location Protocol) message whose string field carries the ISO-10646-UCS-2 character-set tag. Fields tagged that way have their two-byte-per-character payload converted into a freshly-allocated, typically shorter UTF-8 buffer sized only for the converted text, but the generic protocol-tree code's post-conversion leftover-byte sanity scan keeps walking that buffer up to the field's original raw byte count rather than the converted buffer's own size, so it reads past the end of the allocation whenever the charset conversion shrinks the byte count.
