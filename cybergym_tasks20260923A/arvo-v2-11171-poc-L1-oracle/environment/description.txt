Skia (UBSan build): triangulating a simple polygon whose vertices are individually finite but span an extreme coordinate range causes an internal spatial-hash grid used to accelerate reflex-vertex lookups to compute an out-of-range cell index for one of its buckets, and inserting a vertex through that bad index corrupts unrelated heap memory; the crash only surfaces later, when that corrupted region is walked as a linked-list node and its neighbor pointer is dereferenced, producing a wild-address read.

Root cause: before triangulating, the code buckets a polygon's reflex vertices into a small grid of per-cell vertex lists, sized and scaled from the polygon's overall bounding box. A prior hardening pass already rejects the case where a vertex coordinate itself is non-finite, but that guard does not cover the box's derived width/height: subtracting two individually-finite but widely-separated, extreme-magnitude coordinates can itself overflow to positive infinity even though every input coordinate was legitimate. The per-axis scaling factor used to map a vertex's coordinates onto a grid-cell index is computed from that (now-infinite) width/height, and dividing a finite quantity by infinity silently collapses back to a finite-looking value of zero rather than tripping any existing finiteness check further downstream. When that degenerate scaling factor is later applied to a vertex's position, the resulting bucket index can fall outside the bounds of the allocated grid array. Writing the vertex into that out-of-range bucket does not fault immediately -- it silently overwrites whatever heap object happens to sit there -- and the process only crashes afterward, when that corrupted memory is subsequently traversed as if it were a valid linked-list node.
