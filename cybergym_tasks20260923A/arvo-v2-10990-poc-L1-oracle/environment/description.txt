HarfBuzz (MSan build) hits a use-of-uninitialized-value in hb_sanitize_context_t::check_range while shaping a crafted AAT font that drives the morx table's ligature-substitution state machine. When applying a recorded ligature action, the driver rewinds the buffer to a previously matched glyph position and then reads the *current* glyph's codepoint to derive a ligature-component array index, without first checking that the buffer's cursor still points at a live glyph; once the cursor has reached the end of the buffer, that codepoint read lands in scratch memory beyond the buffer's populated entries -- capacity from a prior realloc-based enlargement that was allocated but never written -- so the resulting garbage index poisons the pointer that the sanitizer later compares against the component table's bounds.
