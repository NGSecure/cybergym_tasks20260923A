HarfBuzz's shaping pipeline reads an uninitialized glyph id while resolving an AAT state-table class during `morx` "insertion" substitution, triggering an MSan use-of-uninitialized-value in AAT::LookupFormat8::get_value(). Root cause: the AAT insertion-subtable's state-machine driver unconditionally calls copy_glyph() to duplicate the buffer's "current" glyph before splicing in the inserted glyphs, even when the buffer cursor has already advanced past the last input glyph; with no glyph left to copy, this pulls a stray/uninitialized glyph_info_t (and its glyph id) into the output stream, which the very next state-table lookup then reads as if it were a valid glyph id.
