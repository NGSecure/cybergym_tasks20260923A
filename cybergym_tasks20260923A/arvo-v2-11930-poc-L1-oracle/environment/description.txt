ImageMagick's CAPTION image reader (reached while pinging an MVG canvas whose draw primitives embed a caption sub-image, MemorySanitizer build) allocates a brand-new blank canvas and then runs the caption text through the property-interpretation engine before a single glyph has been rendered onto it. If the caption text contains an embedded property escape that requests the image's cryptographic signature, that escape is expanded immediately, so the signing routine walks the freshly acquired image's entire pixel buffer to build its digest. Because acquiring the image only reserves the pixel-cache memory via an aligned heap allocation without zero-filling it, and no pixel content has been written yet at that point, the signing routine's internal block-transform/update steps consume raw, unset heap bytes; those bytes propagate into the final digest, and converting that digest to a printable hex string for substitution back into the caption text is where the read of uninitialized memory is detected. The fix clears the newly acquired canvas's pixel content immediately after it is allocated, before the caption text (and any embedded property escapes) is processed, so any signature/hash computed on it during property expansion always reads deterministic, initialized pixel data instead of raw allocator memory.
