ImageMagick 对 JPEG 图像做 ping（仅探测元数据、不完整解码像素）时，会从图像的一个 profile 段中取出被声明为 XMP 的字节数据，交给一个不依赖外部 libxml2、体积精简的内置 XML 解析器去解析（用于未启用 XML 委托库的构建配置）。根因：在把候选数据当作 XMP 送入这条内置解析路径之前，没有对其内容做实质性的合法性校验（构建成 stub 时几乎放行一切输入），于是任意声明为 XMP 的畸形字节串都能一路进入解析器；该数据先经历一次宽字符到窄字符的编码转换生成一块堆缓冲区，随后解析器里一个基于 C 字符串语义（依赖结尾哨兵字符）跳过分隔符/空白的扫描例程，在这块转换结果缓冲区上找不到预期的终止边界，于是越过缓冲区末尾多读了 1 个字节，触发堆缓冲区越界读。
